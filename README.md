# Поиск чисел Кита — Бенчмарк производительности

Учебный проект, разработанный в рамках курса по оценке производительности и тестированию надежности аппаратного обеспечения. Программа реализует алгоритм поиска **чисел Кита** (Keith numbers) в заданном пользовательском диапазоне и проводит бенчмарк (замер времени) выполнения вычислений.

## 📖 О числах Кита

**Число Кита** (или репдигитная последовательность) — это натуральное число $N$, которое появляется в специальной последовательности, построенной на его собственных цифрах.

### Алгоритм проверки

1. Число разбивается на цифры.
2. Следующее число в последовательности равно сумме предыдущих $N$ чисел (где $N$ — количество цифр).
3. Если в процессе построения последовательности появляется исходное число, то оно является числом Кита.
4. Если последовательность превышает исходное число — число не является числом Кита.

### Пример для числа 14

```
Исходное число: 14
Цифры: [1, 4]

Шаг 1: 1 + 4 = 5       (5 < 14, продолжаем)
Шаг 2: 4 + 5 = 9       (9 < 14, продолжаем)
Шаг 3: 5 + 9 = 14      (14 == 14, СОВПАДЕНИЕ!)

Результат: 14 — число Кита ✓
```

### Пример для числа 197

```
Исходное число: 197
Цифры: [1, 9, 7]

Шаг 1: 1 + 9 + 7 = 17      (17 < 197)
Шаг 2: 9 + 7 + 17 = 33     (33 < 197)
Шаг 3: 7 + 17 + 33 = 57    (57 < 197)
Шаг 4: 17 + 33 + 57 = 107  (107 < 197)
Шаг 5: 33 + 57 + 107 = 197 (197 == 197, СОВПАДЕНИЕ!)

Результат: 197 — число Кита ✓
```

### Пример числа, которое НЕ является числом Кита

```
Исходное число: 15
Цифры: [1, 5]

Шаг 1: 1 + 5 = 6       (6 < 15)
Шаг 2: 5 + 6 = 11      (11 < 15)
Шаг 3: 6 + 11 = 17     (17 > 15, ПРЕВЫШЕНИЕ!)

Результат: 15 — не число Кита ✗
```

## 🏗️ Архитектура проекта

Проект построен на принципах **объектно-ориентированного программирования (ООП)** и **разделения ответственности (SRP)**. Код разделен на независимые модули, что обеспечивает его переиспользуемость и легкость поддержки.

### Основные классы модуля `module-kit`

| Класс | Ответственность | Описание |
|-------|----------------|----------|
| **`KitChecker`** | Ядро алгоритма | Проверяет одно конкретное число на принадлежность к числам Кита. Использует оптимизацию «скользящее окно» (sliding window) для минимизации потребления оперативной памяти. |
| **`KitFinder`** | Координатор | Отвечает за перебор чисел в заданном диапазоне и строгую валидацию входных данных (защита от некорректных диапазонов). |
| **`KitBenchmark`** | Хронометрист | Обертка над `KitFinder`. Замеряет время выполнения с высокой точностью (`time.perf_counter`) и формирует итоговый отчет. |

## 💡 Особенности реализации

### 1. Оптимизация памяти: Скользящее окно

В алгоритме `KitChecker` используется концепция **скользящего окна** (sliding window). Вместо хранения всей растущей последовательности в памяти, хранятся только последние $N$ элементов (где $N$ — количество цифр числа).

**Пример для числа 197 (N=3):**
```
Начало: [1, 9, 7]
Шаг 1:  [9, 7, 17]     ← добавили 17, удалили 1
Шаг 2:  [7, 17, 33]    ← добавили 33, удалили 9
Шаг 3:  [17, 33, 57]   ← добавили 57, удалили 7
...
```

Это критически важно при тестировании на больших диапазонах, так как предотвращает неограниченный рост потребления памяти.

### 2. Точность бенчмарка

Для замера времени используется `time.perf_counter()`, который:
- Предоставляет наивысшую доступную точность таймера
- Не зависит от системных часов ОС
- Не подвержен изменениям времени (синхронизация с NTP)
- Идеально подходит для коротких промежутков времени

### 3. Кроссплатформенность

Проект полностью поддерживает:
- **Windows** — через `.bat` скрипты
- **Linux** — через `.sh` скрипты
- **macOS** — через `.sh` скрипты

Код не содержит OS-specific вызовов и использует только кроссплатформенные функции Python.

### 4. Валидация и обработка ошибок

Программа строго проверяет входные данные:
- Запрещает диапазоны, где `start > end`
- Запрещает числа меньше 10 (числа Кита начинаются с двузначных)
- Выбрасывает понятные исключения `ValueError` с описанием проблемы

### 5. Принцип повторного использования

Каждый класс спроектирован для независимого использования:
- `KitChecker` можно использовать отдельно для проверки одного числа
- `KitFinder` можно использовать без бенчмарка для простого поиска
- `KitBenchmark` можно интегрировать в любую систему тестирования
